# Практика · Центр-инвест

## Боты под управлением

Во время летней практики 2025 года в банке «Центр-инвест» я работал над frontend-интерфейсом для управления HR Telegram-ботами. За три недели спланировал клиентскую часть: определил стек, реализовал основные пользовательские сценарии и подготовил интеграцию с API, пока backend-разработчик делал свою часть системы.

Наставники помогали через code review: подсказывали, как оформлять запросы, указывали на ошибки в асинхронной логике и помогали улучшать интерфейсные решения. В проекте я впервые плотно поработал с MUI и компонентным подходом к внутренним сервисам.

**Период:** лето 2025  
**Роль:** Frontend-разработчик · практика  
**Стек:** React · TypeScript · MUI · Zustand · React Hook Form · Zod · Axios · React Virtuoso · REST API

## Что реализовал

1. **Авторизация и маршрутизация.** Сделал экран входа, хранилище состояния авторизации на Zustand и защищённые маршруты: без входа нельзя открыть панель и страницы ботов.
2. **Управление ботами.** Реализовал список ботов со статусами и счётчиками новых сообщений, а также сценарии создания, просмотра, редактирования и удаления бота с подтверждением действия.
3. **Формы и валидация.** Собрал формы на React Hook Form, добавил проверки через Zod и понятные сообщения об ошибках.
4. **Настройка анкеты.** Добавил создание вопросов, варианты ответов и удаление вопросов из сценария Telegram-бота.
5. **Ответы пользователей.** Сделал отдельную вкладку со статистикой по ответам кандидатов и раскрывающимися карточками для просмотра деталей.
6. **API-слой и промежуточная обработка запросов.** Вынес HTTP-логику из компонентов в отдельный API-слой на Axios. Использовал Axios Interceptors как промежуточный уровень обработки запросов и ответов: в одном месте можно настроить заголовки, логирование, обработку ошибок и единый формат сообщений для интерфейса.
7. **Работа с большим списком.** Использовал React Virtuoso для виртуализированной таблицы ботов, чтобы список оставался быстрым при увеличении числа записей.

## Технические решения

### Формы и валидация

React Hook Form управляет состоянием форм без лишних перерисовок, а Zod проверяет email, пароль и обязательные поля. Кнопки действий недоступны, пока форма не заполнена корректно.

### Компонентный интерфейс на MUI

Во время практики познакомился с Material UI и использовал библиотеку для таблиц, форм, диалогов подтверждения, вкладок, уведомлений и адаптивной структуры панели. Это позволило быстрее собрать единый и консистентный интерфейс.

### Состояние и навигация

Zustand хранит состояние авторизации. React Router разделяет публичный экран входа и защищённую часть панели. Активная вкладка карточки бота сохраняется в URL, поэтому на неё можно перейти по прямой ссылке.

### Интерфейсные состояния

В приложении предусмотрены скелетоны и индикаторы загрузки, уведомления об успешных действиях и ошибках, подтверждение удаления. Это делает работу с внутренним сервисом предсказуемой.

## Демонстрационная версия

Публичная версия проекта адаптирована для портфолио: вместо внутреннего backend API используются обезличенные демо-данные. Все действия в демо работают в браузере и сохраняются в `localStorage`: вход, создание, редактирование и удаление ботов, а также создание и удаление вопросов. Это позволяет показать пользовательские сценарии без доступа к внутренней инфраструктуре банка.

## Результат

За время практики получил опыт разработки внутреннего React-приложения: от выбора технологий и построения форм до интеграции с API, обработки асинхронных запросов и проектирования состояний интерфейса.

Публичный fork проекта `Center-invest-IT/hr-telegram-bot-admin`. Описание личного вклада составлено по материалам практики; в демо не используются реальные данные банка или кандидатов.
